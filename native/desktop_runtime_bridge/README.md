# Fixed Desktop runtime bridge

Private Windows x64 transport for the colocated native account owner. The
production entry discovers the pinned Desktop image and its direct stdio
app-server. Endpoint selection parses the supported CLI command position; a
same-path auxiliary executable is not sufficient. Process creation identities,
fixed image/module hashes and exact stdout-pipe metadata bind the attachment.

The metadata worker is a short-lived native executable because file-name
queries can wait behind existing I/O. Unknown writable handles remain unknown;
no timed-out query is silently treated as proof. Production requires either two natural request/response pairs or its startup-only
fixed two account/read probe responses on the selected writer. General side writes
are not enabled by unknown-handle classification alone. External auth ABI2 is
retained; internal mapping4 adds independent live and metadata rings.

The bridge never reads the original stdout payload itself. A resident observer
projects finite metadata from the original API path. Private side writes copy
their frame, suppress an unrelated original IOCP notification with an event's
low bit, and retain in-flight storage until completion or target exit. `Busy`
means the new frame was not admitted; `Pending` means that frame is retained.
Write completion is not authentication success. Stop does not restore account
ownership or call logout, and never kills the existing target.

The actual fixed Desktop passed a 30-second read-only acceptance with 619
natural frames, unchanged completed buffers/process identities and restored
IAT/page protection. No credentials or model requests were involved. Actual
credential switching is a later acceptance step, not established by that run.
