# Codex 时区启动器

**本程序由 Codex 开发。** 这是独立的开源桌面项目，并非 OpenAI 官方应用。

这是一个使用 Flutter、Forui 和 Rust 构建的 Windows/macOS 启动器。它为新启动的客户端进程设置指定时区，不修改操作系统的全局时区；已经运行的客户端不会因修改设置而自动切换时区。

## 主要功能

- 选择 120 个常用 IANA 地区时区（含夏令时规则）或 UTC−12 至 UTC+14 的固定偏移，预览本地与目标时间。地区清单重点覆盖美国、亚洲和欧洲，可按城市名称或 IANA 标识搜索；美国包含主要时区及亚利桑那、阿拉斯加、阿留申群岛、夏威夷等特殊地区。
- 自动发现或手动选择客户端，保存配置、检查启动条件并创建桌面快捷方式。
- 查询双线路公网信息、缓存结果、复制 IP，并将可识别的时区用于设置草稿。公网查询会连接第三方服务。
- 默认首页为启动器；窄侧栏提供总览、账号额度、关注与收件箱、数据分析、独立 API 测速；数据分析同页保留额度、最近回合、配置对比、上轮活动、最近响应五类图。最多明确关注 8 个会话并保存 200 条结构化事项；新系统通知打开收件箱，事项按原路径与会话 ID 打开分析。紧凑仪表盘支持浅色、深色和窄窗口，图内选择器只改变显示，不额外查询。账户用量支持手动刷新与保存的自动刷新偏好，本地会话由用户明确选择后只读采集；桌宠暂停。需要可用的 Codex CLI，并为监控来源独立登录；旧版本可能只提供部分统计。口径、空态与提醒规则见[监控说明](docs/monitoring.md)。
- 交互与外观：柔和浅深色、持续悬停的同色光晕与向外飘散粒子；竖柱由下向上、横柱由左向右流动。点击涟漪最多反弹两次，只保留最近两次点击并逐渐消失。数值端点保持固定，同一标记刷新后保留悬停读数，查看数值统一两位小数；“减少动态效果”尊重应用和系统设置。Windows 窗口、任务栏与托盘使用原创时环图标，标题栏和精简的四项托盘菜单跟随主题；高对比度或绘制资源不可用时菜单使用系统样式。
- “独立 API”提供 Chat Completions / Responses 离线回放：选择内置合成场景后手动开始，查看首模型输出、首可见输出和吞吐指标，支持取消及恢复上次观察。回放通过本机 HTTP 链路运行，不代表服务商速度；真实 API 执行尚未开放。
- 支持 Dream Skin 兼容启动、打开管理器和“重新注入皮肤”。重新注入需要当前客户端通过兼容模式启动并开放本机调试端口；此操作不会重启客户端或改变其时区。
- 读取旧版 `settings.json`；用户配置保存在本机，发布包不包含本机设置或日志。

本开发分支加入 Windows Codex 订阅多账号监控，使用监控专用目录中的独立官方登录。本候选已接入六工作区、关注收件箱，以及柔和·雾杉、科技·极昼、石墨·香槟三套可切换主题，每套均支持浅色和深色，默认柔和·雾杉。图表数据、可读控件与装饰使用独立颜色角色；实际账户执行切换仍为后续提案。历史方向与后续需求见[下一阶段建议](docs/2026-10-23-next-stage-proposal.md)，近期参考仓库与依据见[功能研究](docs/2026-10-23-feature-research.md)。

rc21 在新分支重构了工作区排版：总览采用自适应数字入口卡，启动器突出目标时间并分组设置，分析页分离来源、筛选和读数。三套主题与原有交互继续保留；账户、会话和 API 的数据及操作仍分别管理。原审美与本轮离线功能修复另存于 `feature/classic-workspace`，rc20 历史版本仍保留于 `feature/k3-2-readonly-preflight`。本轮也完成 K3.2 离线诊断分层与未来 strict 启动模板整理，没有开放真实任务、热切换或模型请求。

### 字体与后续中英文

Windows 使用 Segoe UI Variable Text，中文回退至 Microsoft YaHei UI / Microsoft YaHei；其他平台保留 PingFang SC、Noto Sans CJK SC 回退。它们是适合屏幕界面的平台字体，但不存在人人最舒适的唯一字体。可读性还取决于字号、字重、行距、对比和控件留白；参见 [Windows 字体指导](https://learn.microsoft.com/en-us/windows/apps/design/signature-experiences/typography) 与[微软雅黑说明](https://learn.microsoft.com/en-gb/typography/font-list/microsoft-yahei)。

当前应用文案仍为中文，尚未提供中英文切换。后续采用共享自适应布局和资源字符串，按语言处理字体回退、文本长度及日期数字格式，而非复制两套页面或缩小英文强行塞入中文宽度。账号栏现在将标签置于控件行上方；分析页的来源、类型、视图按字段组留白，并验证 125% 字号。国际化实现依据 [Flutter 官方文档](https://docs.flutter.dev/ui/internationalization)。

### K3.0 多账号独立任务：离线能力原型

本分支新增仅参与 Rust 测试的所有权与生命周期原型，不增加生产执行入口。合成任务分别绑定来源、身份观察键、来源代际、工作区键、任务与执行代际，再绑定线程和回合；审批带独立请求 ID，消费一次。取消提交不会直接宣告结束，断线与恢复先显示待核对，保留取消意图；只有匹配的终结事件与自己的清理确认后才能释放占用。

这些测试只证明离线路由契约，尚未证明真实认证主体或上游并发执行。真实执行、热切换当前 Codex、迁移运行回合和自动续接均未开放。发布二进制不包含此测试模块；现有多账号功能仍是监控。

K3.1 已加入 Windows 独立假进程验证：清空继承环境，明确各自 CODEX_HOME 与工作目录，验证有界双向管道、审批/通知路由、取消和 Job 后代清理。任务占用复用 `account_sources` 的内存所有权与排他文件锁；同源查询/登录返回 busy，移除不能隐式取消任务，退出等待自己的运行时清理。文件锁现在先于 profile 验证取得，避免跨实例删除空隙。只有完整进程身份匹配的清理回执才能解锁；终结事件本身不释放凭据占用，断线不能显示为完成。

K3.2 增加托管查询的握手目录核对：服务报告的目录缺失、不存在或不匹配时，在读取配置与账号之前失败，不回退到当前账号。恢复官方只读核验后，已修复固定版本通知时间戳及初始化状态通知的兼容问题；两个连续独立子进程均成功读取管理要求、有效 `file` 凭据配置，四次账号读取均正确显示未登录。rc22 随后由用户完成专用来源官方登录，实测登录后额度读取、再次手动查询，以及仅重启候选后的来源选择、额度缓存恢复和再次查询均成功；返回的身份字段只在内存比较，观察一致。此结果限于一个独立来源，第二账号、凭据续期和强账号主体/工作区同一性尚未验证。真实任务和热切换继续关闭。详见[核验边界](docs/monitoring.md#k32-只读能力核验)。

这是自建假服务与真实进程/文件锁的组合验证，运行器仍仅参与 Windows 测试，不是正式账号任务入口。Job 使用可信夹具的启动屏障，不证明任意程序的原子启动安全；规范路径和同用户 ACL 也不构成恶意同用户进程的安全沙箱。当前固定 CLI 的静态 schema 已重新核对，文件参数被接受不代表真实凭据存储、续期或主体连续性已验证。后续须先核对官方只读握手及有效配置、明确来源登记/身份代际，再决定是否开放有界真实任务；不能根据模拟成功自动开启真实执行。

### Codex 订阅多账号监控（Windows 候选版）

在账号额度工作区添加来源并命名，手动进入官方浏览器登录。账号列表只包含独立登录的监控来源，不再自动登记当前 Codex 为“默认来源”。新增登录不改变当前 Codex 的认证，不重启它，也不发送模型请求；额度查询不需要另外充值 API。程序先核验本机 CLI 的协议、空目录隔离与实际生效的文件凭据存储方式，验证失败就停止新增登录。

账号选择器只改变额度图；总览以独立额度环、重置时间轴和来源状态对比账号，不合计百分比。同邮箱来源保持独立，工作区和共享额度归属无法确认时不自动合并。本地会话图仍来自明确选择的日志，不随账号选择重新归属。托盘可固定另一个来源，托盘刷新针对固定来源。

默认每来源两分钟刷新，全局串行并错峰执行。网络失败保留原时间的旧读数；认证失效清除过时额度，不能显示成满额度。重启恢复来源目录、选中项、托盘固定项和缓存；历史缓存、首次低额度读数或切换来源不会补发旧提醒。旧配置中的默认来源会被忽略，选中项和托盘固定项改选可用的独立来源；没有账号或移除最后一个账号时显示添加空态，不回退到当前 Codex。

| 本地文件 | 内容 |
| --- | --- |
| `account-sources-v1.json` | 来源别名、选择、缓存时间和提醒摘要，不含登录凭据 |
| `account-profiles/profile-*` | CLI 管理的独立登录与内部状态，使用 Windows 当前用户访问权限 |

这些文件位于候选程序旁。CLI 的 `auth.json` 是凭据文件，文件权限保护不等于加密；不要将登录后的整个程序目录当作干净发布包分享。发布包和源码归档不包含本机来源、凭据或日志。移除受管来源只删除该监控目录，不代表撤销服务端授权。取消会停止本程序持有的登录任务，但不能撤销已在浏览器完成的授权。

本地候选使用 `Start-Candidate.cmd`；合成体验程序在独立测试目录，顶部明确标注合成账号与会话。空目录和回放测试不替代真实双账号、登录续期与额度网络验收；这些结果单独记录在交付报告中。独立来源目前只查询额度。实际账号切换与云端同步不在本阶段。

账号额度和账号总览已移除重复的“查看数值”。其它图表在页面或悬停已完整显示同一记录时也不再重复提供弹窗；仅对超出悬停视口的长文本、未绘制区间或零面积标记的额外明细保留入口。

## 下载与运行

在 [GitHub Releases](https://github.com/iUshio/codexTimeZoneRev/releases) 下载对应平台的 ZIP。Windows 解压后运行 `codex_timezone.exe`，并保留同目录的 DLL 和 `data` 资源。macOS 解压后运行应用；当前 macOS 包仅使用临时签名，尚未完成 Developer ID 签名与公证，系统可能要求用户手动确认打开。

### Windows 启动排错

右上角“主题”菜单可分别选择配色风格和明暗模式。默认“柔和·雾杉”，另有正蓝的“科技·极昼”和克制浅金重点的“石墨·香槟”；每套均支持跟随系统、浅色、深色。正常入口保存这两项独立偏好，离线试用仅本次生效。更换外观不查询来源、不重置页面或草稿。

本开发分支默认显示启动器。常规直接启动 `codex_timezone.exe` 时，自动额度刷新与本地会话采集按实际保存设置运行；关闭主窗口后既有后台采集和独立通知可继续工作。桌宠仍暂停。五类图在“数据分析”同页展示，独立回放在“独立 API 测速”工作区运行。候选包应包含 `docs/monitoring.md`，界面“监控说明”只打开该本地文档。当前候选未自动发布至 GitHub Releases；旧阶段文档保留历史行为，不作为新候选使用说明。

紧凑仪表盘离线候选请解压到新目录，运行 `Start-Trial.cmd`。该入口启用进程内离线策略，使用目录内的空 `CODEX_HOME`，阻断公网信息、账号查询、真实会话采集及目标客户端启动；不读取密钥、不发送真实 API 请求，也不修改全局偏好。未注入合成夹具时日志显示空态；明确标记的合成入口可显示预先准备的关注与事项，独立 API 可手动运行合成回放。候选入口使用不透明背景，便于查看完整配色。`Stop-Trial.cmd` 请求同目录测试实例正常退出。不同目录各有实例身份，请一次只开一个候选。详细口径与中断恢复规则见[独立测速说明](docs/monitoring.md#独立测速离线回放)。

Windows 启动器会在建立 Dart 运行环境前清除自身继承的 `TZ`，使“本地时间”使用 Windows 系统时区。给新启动目标客户端设置的所选时区仍独立生效；本修复不修改系统时区或已经运行的 Codex。

Windows 版 0.2.3 内置 MSIX 包身份兼容引导，直接双击 `codex_timezone.exe` 即可，无需额外 CMD/PS1。启动器在普通桌面环境启动后重新发现当前注册的 Codex 包，通过 Windows 自带 PowerShell 的 `Invoke-CommandInDesktopPackage` 进入正确包身份，再显示原界面。不会请求管理员权限、改写包权限或关闭正在运行的 Codex。内部交接验证包版本和应用身份，失败或超时会停止重试并记录原因。

该兼容路径针对 Windows 更新后直接创建 Store 客户端进程返回“拒绝访问（错误 5）”的情况。这个错误本身不证明权限损坏，请勿因此重复修改 ACL。微软将上述命令定义为调试接口，其上下文不与正式应用激活完全等同；未来系统或客户端更新后仍应复检。

可运行 `codex_timezone.exe --verify-launch` 做无界面检查：只创建、校验并清理挂起的客户端，不执行客户端代码。结果在 `data/context-check.json`，退出码 0 表示通过；引导日志在 `data/context.log` 和 `data/context-bootstrap/`，原生检查日志在 `data/preflight.log`。这些检查不会覆盖 `data/launch.log`。新客户端实际显示时区须在用户自然关闭旧客户端后验证。

对于 Microsoft Store / MSIX 安装的客户端，每次启动都会重新识别当前注册版本；设置中保存的旧 Store 版本路径会跟随更新。普通手动安装路径保持原选择。新进程在执行前核对程序包与应用身份。

若检测到受支持的 `15700 / 15703` 身份缺失，点击“一键修复并重试”，再确认 Windows 管理员提示。启动器先备份权限，仅将当前 Codex 包的一条已知异常普通用户规则从读取和执行缩小为读取，保留包身份条件执行权限、所有者及其他规则。完成后重新检查身份，并按原时区和皮肤设置重试一次。取消授权、权限不符合条件、版本变化或复检失败都会停止；不会关闭现有客户端。正常启动不会请求管理员权限。

权限备份、修复结果和日志保存在 `data/repairs/repair-*/`。需要回退时，核对该次 `plan.json` 后在管理员 Windows PowerShell 中运行同目录的 `repair_package_acl.ps1 -Mode Rollback -PlanPath <plan.json绝对路径>`；脚本仅接受原版本和符合备份的权限状态。回退可能恢复原启动故障。请勿重置整个 WindowsApps 的权限。

此流程用于在更新后再次出现已知权限问题时恢复启动，不保证未来客户端版本或未知权限变化均可自动修复。修复脚本内置在 DLL 中，完整发布包不依赖本机 diagnostics 文件夹。

启动阶段、目标版本、所选时区和原生错误会写入启动器旁的 `data/launch.log`，不记录完整环境变量。普通启动提示仅确认进程已启动；客户端窗口就绪及最终显示的时区仍需实际确认。

## 从源码构建

需要 Flutter 3.47.5（Dart 3.13.4）、Rust stable。Windows 还需要 Visual Studio C++ 桌面工具链；macOS 需要完整 Xcode。将 Flutter 的 `bin` 与 Cargo 加入 `PATH`，或在 Windows 传入 `-FlutterSdk`。

```powershell
# Windows：在仓库根目录运行
.\scripts\flutter-windows.ps1 -Action test
.\scripts\test-native-windows.ps1
.\scripts\test-package-acl-repair.ps1
.\scripts\test-repair-entry.ps1
.\scripts\test-bootstrap-windows.ps1
# 可选：以安装 Codex 的用户验证当前包身份、旧路径跟随更新和过期修复拒绝；不执行客户端代码。
.\scripts\test-native-windows.ps1 -InstalledPreflight
.\scripts\flutter-windows.ps1 -Action build
```

```bash
# macOS：在仓库根目录运行
bash scripts/flutter-macos.sh test
bash scripts/flutter-macos.sh build
```

构建产物位于 `environment/artifacts/`。发布版的 Windows/macOS 云端构建仅由 GitHub Release 的发布事件触发；向 `main` 推送代码不会启动此工作流。构建完成后，ZIP 会附加到该 Release。

### 额度观测历史

账号额度页的「历史与节奏」在同一页展示趋势、日×小时观测余量和变化/查询异常。沿用页面唯一的额度来源选择器；登录分段、额度桶、窗口与时间过滤只读取本地历史，不查询额度，也不改变托盘固定来源、本机会话日志或独立 API 测速选择。默认当前登录段和最近 7 天；新登录段没有记录时保持为空，旧段需显式选择。旧段选择项中的日期表示当前检索范围，实际记录时间见图表下方。

- 趋势纵轴固定 0–100%，可切剩余/已用。点代表真实查询观测，线只连接允许连续比较的相邻观测；未知、失败、窗口/登录段变化和明显缺口不补零。密集列仅保留真实首末与极值点，列内存在断点时不连线。悬停或聚焦后用方向键读取两位小数、时间质量与间隔；密集视图注明“距前绘制观测”，并非逐条原始采样间隔。
- 热力图默认取该小时**已观测的最低剩余比例**，也可取最后一次观测剩余。这不等于完整小时的真实最低值、消费强度、活跃度或 token 消耗。没有有效样本是未知；失败与缺口分别叠加标记，不能由低值颜色推断网络故障。只有一次样本时读数明确标注。日期/小时用系统本地时间，同一天夏令时重复小时按 UTC 偏移分行，绝不合并。
- 变化轴展示观测之间的已用比例上升/回落、报告重置时间变化、跨过旧报告时点、查询异常及未观测间隔。选择一项会在趋势中标记整个观测区间；比例下降不证明“重置完成”，缺口不代表零用量。长列表在固定高度内按需构建。
- 汇总读数属于所选范围，不是实时余额；实际记录范围包括可读完成记录，可能比请求范围短。成功观测来自已有唯一查询 owner；打开、切换和筛选历史不会新增采样或联网请求。历史页打开期间，已有查询完成会触发本地重读，无独立刷新定时器。

历史按 UTC 日保存在当前候选自身目录 `quota-history-v1/<sourceId>/YYYY-MM-DD.jsonl`，只记录来源/分段 ID、额度、时间和白名单状态，不保存身份原文、凭据、提示词或回答。默认保留当前 UTC 日及前 29 日；单来源约 25,000 条、总计约 100,000 条为启动/跨 UTC 日按最老日文件清理的目标，运行中可能暂超，实际可少于 30 天。移除来源成功后清理其本地历史；写入、读取或清理错误会独立提示，不将旧余额伪装成新采样。损坏记录保留原文件并呈现可读部分及缺失提示；不会自动导入旧候选目录。

### 会话节奏（本地多会话复盘）

数据分析页默认「当前会话」，保留原有五图；「会话节奏」在同页显示日×小时热力图、活动泳道和完整回合耗时箱线/样本点。点击「来源」再明确列出和加入本地主会话，最多 8 个；此选择不会改变当前日志、账号、API 测速或关注提醒。默认近 7 天，可选近 24 小时/30 天；悬停读数驻留，方向键检查，点击或回车选择，小时筛选可清除。

计数按明确终态时间归日，取消单列；活动只来自有效 item 区间，跨会话汇总取并集，不是人工工时、纯推理或网络时间。分布仅统计合法的已完成完整回合耗时，R7 四分位，少于 5 个样本只画点；数值以两位秒数显示。未知、部分、截断、缓存待重读与读取错误分别标示。夏令时重复小时保留独立 UTC 身份和偏移读数；没有数据的小时不补活动零值。

候选目录的 `session-rhythm-v1.json` 仅保存明确来源引用与白名单派生回合事实，不含正文、命令、参数、item/response ID 或账号信息。重启只恢复缓存，不自动读真实日志；加入来源或「重读本地日志」才读取，无新增周期轮询。缓存按读取时刻保留近 30 天相关事实及时间未知事实，单来源最多 25,000 条；损坏/保存失败可见，旧缓存不会冒充本次成功。预览、离线和注入后台默认内存存储。

「打开来源分析」使用原路径和预期会话 ID，并单独保留历史回合上下文。下方五图仍属于该来源当前可用观测，不能冒充历史回放；身份不匹配时显示错误，不选替代来源。详细口径见 [监控说明](docs/monitoring.md)。
