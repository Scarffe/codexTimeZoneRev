# 下一阶段建议：账户观测与任务归属

> 历史提案快照，不是当前待开发清单。此后J、K1/K2、U1/U2已分别推进，真实任务/热切换继续后置；当前范围以根目录 [自主路线](../AUTONOMOUS-ROADMAP.md) 为准。下文的“未实现”描述提案写作时，不覆盖后续交付。

状态：需求分析，未实现。近期参考仓库、维护日期、许可证、来源和适配边界见[研究记录](2026-10-23-feature-research.md)。本轮动效、涟漪与托盘修复不同时加入账户写入或新主题家族。

## 建议先做什么

优先做多账户观测。当前单账户额度和明确选定的一个会话已经可用；新增价值应是回答“哪个账户还有余量”“哪项任务需要我处理”，而不是继续增加相同口径的图表。

| 阶段 | 可验收交付 | 边界 |
| --- | --- | --- |
| J1：账户目录与缓存比较 | 别名、明确来源、逐账户最近快照、更新时间、独立错误；选择 B 只改变查看目标 | 先用合成或已有明确来源的快照；不导入认证、不切换登录，不因无快照制造 100% |
| J2：逐来源查询能力验证 | 核查独立 profile/home 是否受支持、身份是否稳定、续期是否写盘、并发写者是否安全；逐账户缓存与失败退避 | 实际登录、认证登记与跨账户查询另定方案；“只读业务方法”不保证认证续期零写 |
| J3：多账户总览 | 同页额度卡、重置日历、逐行刷新及观察历史；区分选中、查询、当前运行身份 | 共享额度池有稳定标识才去重；不同账号百分比不可相加；不自动轮换或重启客户端 |
| K：多会话待处理队列 | 显式固定多个本地会话，按可靠事件显示运行、已完成或待操作；通知定位原 session/turn | 文件时间不当作运行状态；取消/读取失败不当作完成；无确定事件不称等待审批；不自动 resume 或发送内容 |
| L：跨日账本与额度节奏 | 每日/项目/模型用量、增量扫描、可复算时区分组、额度快照趋势 | 日志 token、额度百分比、API 等值价格与订阅实付保持区别；覆盖不足不给预测 |

真实账户切换应独立设计：操作系统安全存储、更新前比较、并发续期、备份和恢复日志，以及对已运行客户端是否生效的明确说明。API provider 切换也应与订阅账号切换分开。它们不属于 J1 的按钮顺带功能。

## 主题应是一套系统

每个风格同时设计浅色与深色；窗口、标题栏、图表、菜单和状态色共享角色。建议保留三套候选，而非把浅色和深色分别当成不相关的皮肤。

| 候选 | 默认感觉 | 强调色使用 | 注意事项 |
| --- | --- | --- | --- |
| 柔和·雾杉 | 暖灰浅色与低亮石板深色，适合长时间监控 | 蓝绿主要操作、灰紫推理、绿色工具 | 推荐默认；降低大面积亮度，仍须保持文字对比 |
| 科技·极昼 | 冷灰与深蓝，信息清晰 | 青蓝焦点、鸢尾辅助系列 | 光晕限于悬停，避免常亮霓虹和大面积渐变 |
| 石墨·香槟 | 米灰与石墨，克制金色 | 金色用于选中与主操作，数据仍保留多色区分 | 不将全部系列染金；大面积高亮金会损害层级 |

霓虹可作为局部交互点缀，不建议用作长期常驻的全屏基底。增加视觉效果应先确定活动条件、对象上限、淡出及减少动画策略。三套配色预览为代码绘制的概念稿、合成数据，不是实际程序截图，也没有加入设置开关。

## 可形成自身特色的组合

1. **下一次启动会怎样。** 把当前已核对的运行身份/时区与下一次启动草稿并排，附本地与目标时区的重置日历。查看不会改变正在运行的客户端。
2. **读数为什么变了。** 对比来源、账号、方案、窗口、更新时间和核验原因；提供对应合成回放。无法归因时保留未知，不猜测网络或模型故障。
3. **任务容量排演。** 用用户输入的任务范围、已观察额度与重置点展示保守/中性情景。样本不足明确显示，完全本地计算，不试跑模型，不把百分比精确换算 token。

这些是结合本项目特点提出的设计组合，不宣称全球首创。建议先完成 J1，再根据真实使用反馈决定 J2/J3；不要同时引入代理路由、账号自动轮换、手机同步和真实 API 消费。
