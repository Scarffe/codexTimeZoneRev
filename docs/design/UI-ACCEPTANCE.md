# Flutter 界面验收

先阅读 DESIGN.md。按本次修改范围选择验证，不为单纯文字或颜色修改运行无关全量测试。

## 人能否理解并操作

- 主要任务有清楚入口，保留启动、账号、监控、分析及设置功能；切换页面不丢失控制器和选择状态。
- 会话名称来自明确本地元数据；无名称时显示可读回退。相同名称仍能按独立 ID / 路径正确打开。
- 完整名称可在提示或详情查看；完整 ID 和路径保留复制能力。
- 列表排序、分页、筛选后从结果开头阅读；后台更新同一结果时不打断阅读位置。
- 未知、部分覆盖、错误、过期和空数据应如实呈现，不把缺失数据显示为零或已确认。

## 布局与视觉

- 使用实际 Flutter 渲染和 Windows 字体。截图测试注明合成数据，不能代替真实账号或客户端链路验证。
- 对受影响页面检查浅/深色、中/英文、760/1280 宽度和 125% 字号；影响响应式控件时加窄宽度。
- 宽导航有文字，窄导航有提示/语义标签；标题、控件、卡片与图表之间有清楚层级。
- 留白服务于分组，避免重复边距、单行控件不必要地独占多行，以及长内容推走关键操作。
- 保留三套配色、语义颜色与减少动态效果偏好。装饰性动效不能干扰操作或成为信息载体。

## 完成证据

记录相关组件/原生回归、静态检查、截图路径、构建版本和仍未验证的真实链路。失败必须保留并说明修复或复跑结果，不能只报告最后一次通过。

参考的字体、留白、层级、色彩、动效、微交互、响应式与原创性是检查维度；不使用“再无任何可改进处”作为无限验收条件。
